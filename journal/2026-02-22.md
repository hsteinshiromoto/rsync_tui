# 2026-02-22 - TUI Visual Modernization (Charm-Inspired)

## User Request

Modernize the terminal user interface following the visual style of the Charm ecosystem repositories (bubbletea, lipgloss, gum). The user chose to stay in Rust with ratatui rather than rewriting in Go.

## Reasoning

The Charm ecosystem (Go-only) defines a modern TUI aesthetic: rounded borders, vibrant RGB colors, pill-style badges, bold typography, and generous spacing. These visual patterns can be replicated in ratatui using `BorderType::Rounded`, `Color::Rgb()`, `Modifier::BOLD`/`ITALIC`, and styled `Span` composition.

Ratatui 0.30 was initially targeted but requires Rust 1.85+; the system has Rust 1.81.0 (managed via nix). Ratatui 0.27 was chosen as the highest compatible version with all needed features (rounded borders, `Block::bordered()`, `Stylize` trait).

## Solution

1. Upgraded ratatui 0.26 to 0.27, removed direct crossterm dependency (using ratatui's re-export).
2. Created `src/ui/theme.rs` with a centralized Charm-inspired RGB color palette and style helper functions.
3. Rewrote all 7 render functions in `src/ui/layout.rs`:
   - Rounded borders on all panels
   - Pill-style numbered titles (e.g., ` 1 ` badge + ` Source `)
   - Pill-style colored option toggles (purple enabled, dark gray disabled, pink key highlight)
   - Mode indicator as colored badge (teal NORMAL, pink INSERT)
   - Color-coded logs (green command prefix, red errors, dim secondary text)
   - Themed progress gauge (purple filled, dark gray track)
   - Color-coded help bar (lavender bold keys, gray descriptions)

## Cross-File Relationships

- **theme.rs <- layout.rs**: All render functions in `layout.rs` reference `theme::` constants and helpers for colors and styles. This decouples visual theming from rendering logic.
- **ratatui::crossterm <- main.rs, event.rs**: After removing the direct crossterm dependency, both files import crossterm types through ratatui's re-export (`ratatui::crossterm::`).
- **app.rs -> layout.rs**: The `App`, `Mode`, and `Panel` types from `app.rs` drive all rendering decisions in `layout.rs` (active panel highlighting, mode badges, content display). No changes were needed to `app.rs`.
- **rsync/command.rs -> layout.rs**: `format_command()` is used by `render_logs()` to display the command preview. No changes were needed to `command.rs`.
- **Cargo.toml -> all**: The ratatui version bump from 0.26 to 0.27 changed the crossterm re-export path, requiring import updates in `main.rs` and `event.rs`.
- **Rust 1.81 constraint**: Ratatui 0.28+ pulls in `darling` and `instability` crates requiring Rust 1.88+, which forced targeting 0.27 instead of 0.30. The nix system config manages the Rust toolchain.

# 2026-02-22 - Tokyo Night Color Scheme

## User Request

Change the color scheme from Charm-inspired palette to Tokyo Night (https://ansicolor.com/). Only theme colors should change; no functional modifications.

## Reasoning

The Tokyo Night palette is a popular dark theme with softer, cooler tones compared to the high-contrast Charm palette. The centralized theme.rs architecture (from the earlier modernization) made this a straightforward constant-swap operation. The build evaluator also identified 6 sets of duplicated RGB literals across semantic aliases, which were consolidated to reference base palette constants.

## Solution

1. Replaced all color constants in `src/ui/theme.rs` with Tokyo Night values:
   - `PURPLE` (#7C3AED) → `BLUE` (#7aa2f7) as primary accent
   - `LAVENDER` (#A78BFA) → `PURPLE` (#bb9af7) as secondary accent
   - `PINK` (#EC4899) → `CYAN` (#7dcfff) as highlights
   - `SUCCESS` (#34D399) → `GREEN` (#73daca)
   - `ERROR` (#F87171) → `RED` (#f7768e)
   - Added `ORANGE` (#ff9e64) for INSERT mode badge
   - Added private `BG_DARK` (#1a1b26) and `TERMINAL_BLACK` (#414868) as base constants
2. Updated `src/ui/layout.rs` references to match new constant names.
3. Consolidated 14 duplicated RGB literals into references to 8 base palette constants (e.g., `PROGRESS_FILLED = BLUE` instead of repeating `Color::Rgb(122, 162, 247)`).
