# 2026-07-04 - Application Review, Critique, and Improvement Plan

## User Request

Review the rsync_tui application, critique it, and deliver an improvement plan. Constraint: the TUI must stay on ratatui (no framework switch).

## Reasoning

Followed the standard agent workflow: the Product Manager agent assessed the request as complex and raised three scope questions, which the user answered via choice menus:

1. **Toolchain**: two-phased — Phase 1 improvements must work on ratatui 0.27 / Rust 1.81; the nix toolchain upgrade + ratatui 0.30 migration is a separate Phase 2.
2. **Deliverable**: commit-ready markdown at `docs/improvement_plan.md` plus this journal entry.
3. **Scope**: unified roadmap — critique-driven fixes folded together with the known pending features (JSON config persistence, exclude-pattern UI).

The full source (~1,500 lines across 10 files) was read directly; the Plan agent structured the verified findings into a phased roadmap; the Plan Evaluator agent independently re-verified the claims against the code and returned NEEDS WORK (minor). Its two should-fix items (wrong module paths in the critique table; missing concurrent-run guard finding) and four nits (C5 overstatement, B.1 dependency over-constraint, missing empty-path validation, M10 MSRV wording) were all folded into the final document.

## Key Findings (verified in code)

| Sev | Finding |
|-----|---------|
| Critical | `run_rsync` executes synchronously inside the event loop (`src/main.rs:177-276`): UI freezes for the whole transfer, progress never renders live, no cancel; tokio declared but unused |
| Critical | Dry-run data-loss bug (`src/main.rs:234-260`): `find <source> -type d -empty -delete` is not guarded by `dry_run`, so a preview with DelSrc on deletes empty source directories |
| Critical | Pipe deadlock risk: stdout drained to EOF before stderr (`src/main.rs:207-231`) |
| Critical | rsync progress is `\r`-terminated so `lines()` misses live updates; `opts.progress` force-set, overriding the user's toggle; `progress_per_file` field name inverted vs `--info=progress2` |
| High | No panic hook (terminal left raw); no input cursor; no confirmation for `--delete`/`--remove-source-files`; unbounded log memory; fixed layout truncates small terminals; exclude patterns unreachable from UI; exit code shown as `Some(23)`; no empty-path/concurrent-run guard |
| Med | Option mappings duplicated in 3 places via magic indices; UTF-8 byte-slicing panic in `wrap_command`; broken Makefile (`.PHONY` missing colon — verified: `make test` fails "missing separator"); README/CHANGELOG drift; unused deps |
| Toolchain | nix environment inconsistent: rustc 1.81.0 with clippy 0.1.95 (Rust 1.95) → clippy unusable (E0514) |

## Accepted Solution

`docs/improvement_plan.md` — a three-phase roadmap:

- **Phase 0 — Safety & hygiene** (7 small independent items): dry-run delete guard, panic hook, Makefile fix, dependency pruning, empty-path guard, exit-code mapping, docs sync.
- **Phase 1 — Core architecture & UX** on ratatui 0.27 (5 workstreams): threaded rsync runner (`std::thread` + `mpsc`, cancel, `\r`-aware live progress), confirmation modal for destructive flags, real cursor editing, bounded buffers, scrolling, data-driven OPTIONS table, tests, JSON config persistence, exclude-pattern UI.
- **Phase 2 — Toolchain & ratatui 0.30**: coherent nix toolchain ≥ 1.88, ratatui 0.30 migration, clippy re-enabled.

Every Phase 1 item was evaluator-verified as feasible on ratatui 0.27 / Rust 1.81 (`frame.set_cursor` and `Clear` exist in 0.27). Each phase has explicit acceptance criteria. No source code was modified in this task.

- **main.rs ↔ rsync/options.rs ↔ ui/layout.rs**: tracing the option toggles across the three files exposed the triplicated key/label/flag mappings (finding M2) and the inverted `progress_per_file` naming (C5) — the layout pill labels are correct but the field name and the mode-blind `parse_progress` in main.rs conflict.

## Cross-File Relationships

- **options.rs → main.rs + command.rs**: the dry-run guard was deliberately placed on `RsyncOptions` so the execution site and the preview cannot drift apart — the original bug existed precisely because the two sites each open-coded the condition. The guard checks the *effective* options clone (Ctrl+n forces `dry_run = true` on the clone), not `app.options`.
- **main.rs ↔ event.rs**: removing `is_quit` required confirming `main.rs` handles quit itself (`q`/Ctrl+c in `handle_normal_mode` and the global handler).
- **Cargo.toml ↔ src/**: grep for `tokio::`/`serde` confirmed tokio had zero usage while anyhow is used in `main.rs`/`event.rs` signatures — hence tokio dropped, anyhow kept.
- **docs/improvement_plan.md → implementation**: each change maps 1:1 to plan items 0.1–0.7; Phase 1 concerns (threaded runner, confirm modal) were deliberately not touched.
