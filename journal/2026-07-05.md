# 2026-07-05 - Phase 1 WS-A: Threaded Rsync Runner

## User Request

Continue implementing the improvement plan (`docs/improvement_plan.md`). After Phase 0, the next step was Phase 1 workstream WS-A (items A.1–A.4) — the plan's centrepiece — plus B.3 (bounded buffers), which the plan's dependency notes say should ride along with the runner rewrite.

## Reasoning

The core defect (C1) was that `run_rsync` executed synchronously inside the event loop, freezing the UI for the whole transfer. The fix extracts execution into `src/rsync/runner.rs`: rsync is spawned with stdout and stderr each read on their own `std::thread`, both sending `RsyncEvent`s (`Line`, `Progress`) into one `std::sync::mpsc` channel. The main loop drains the channel non-blockingly every 100 ms tick and keeps drawing. Completion is detected via channel disconnection — the original `Sender` is a local in `spawn()` that drops on return, so the channel disconnects exactly when both reader threads finish, after which `child.wait()` reaps the process without meaningful blocking. Cancel is `Child::kill` (Esc in Normal mode, or Ctrl+c while running; Ctrl+c still quits when idle). No tokio — std only, per the minimal/stdlib standard.

The org's monthly spend limit interrupted the build-evaluator subagent, so the evaluation was performed inline instead (channel lifecycle, kill/reap ordering, dry-run guard carry-over, progress semantics) with verdict PASS.

## Accepted Solution

| Item | Change |

## Cross-File Relationships

- **runner.rs ↔ main.rs**: the channel protocol is the contract — runner threads own the pipes and parsing; `main.rs` only consumes typed events. Completion detection relies on `spawn()` *not* retaining a `Sender` (a retained clone would mean `Disconnected` never fires and transfers would never be reaped).
- **options.rs rename ripple**: `per_file_progress`/`global_progress` touched `command.rs` (flag emission), `layout.rs` (pills), `main.rs` (toggle comments), and tests in three files — exactly the duplication that plan item C.1 (single OPTIONS table) will collapse.
- **app.rs ↔ layout.rs**: removing `progress_output` required re-pointing `render_progress` to the shared `logs` buffer; the `[ERR]` prefix convention (set in runner.rs) is what layout's red styling keys on.
- **Phase 0 → WS-A**: the dry-run guard survived the rewrite because it lives on `RsyncOptions` (not in the deleted execution code) — validating the Phase 0 design decision to put it there.
